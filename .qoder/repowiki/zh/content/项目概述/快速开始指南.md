## 简介
hexo-theme-fomalhaut 是一个「克隆即用」的 Hexo 站点模板，主题基于 Butterfly 深度二次开发，并把站点配置和主题代码彻底分开。你只需要改配置文件，就能搭建自己的博客；升级主题时也不会冲掉你自己的改动。

本指南的目标是让你在 **10 分钟内**完成环境准备、克隆仓库、安装依赖、本地预览、修改站点信息、写一篇文章并生成静态页面。

## 环境准备
在开始之前，请确保你的电脑满足以下最低要求：

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | **18 / 20 / 22 LTS**（推荐 22） | 仓库声明 `engines.node >= 18`，GitHub Actions 使用 22.x |
| npm | **9+** | 随 Node.js 一起安装 |
| Git | 任意较新版本 | 用于克隆仓库和部署 |
| Hexo | **6.3.0** | 已写进 `package.json`，通过 `npx hexo` 使用，无需全局安装 |

如果你已经安装了 Node.js，可以在终端运行：

```bash
node -v
npm -v
git --version
```

如果提示找不到命令，请先安装对应软件。

## 克隆项目与安装依赖
打开终端或命令行工具，进入你想放项目的目录，然后执行：

```bash
git clone https://github.com/N1280851853/my_blog.git my-blog
cd my-blog
npm install
```

如果你希望更稳定地按锁定版本安装，也可以使用：

```bash
npm ci
```

安装完成后，项目会下载所有依赖到 `node_modules/`，并准备好 Hexo、Gulp、Markdown 渲染器、搜索插件等组件。

> 注意：不要在这个目录里执行 `hexo init`。  
> 这个仓库已经是完整的站点模板，`hexo init` 会重置 `_config.yml`，导致站点配置丢失。

如果你想把远程仓库换成你自己的 GitHub 仓库，可以执行：

```bash
git remote set-url origin https://github.com/你的用户名/你的仓库名.git
```

## 本地开发：启动预览
依赖安装完成后，直接启动本地服务器：

```bash
npx hexo server
```

启动成功后，浏览器访问：

```
http://localhost:4000
```

此时你应该能看到主题的首页、侧栏、示例文章和导航菜单。

### 开发时的热更新行为
- 修改 `source/` 下的 Markdown 文章、CSS、JS 等内容，Hexo 会自动重新渲染。
- 修改 `themes/fomalhaut/` 下的 `.pug` 模板后，需要**重启 `hexo server`**，因为 Hexo 只在启动时读取模板。

如果你只想启动服务而不想每次手动输入命令，也可以运行：

```bash
npm run server
```

## 基础配置修改
hexo-theme-fomalhaut 有两份关键配置文件：

| 文件 | 作用 | 你应该重点改什么 |
| --- | --- | --- |
| `_config.yml` | 站点级配置 | 标题、作者、语言、域名、部署地址、插件开关 |
| `_config.fomalhaut.yml` | 主题级配置 | 头像、社交链接、顶部图、菜单、评论、主题色、侧栏卡片 |

### 第一步：修改站点配置 `_config.yml`
至少检查并修改这些字段：

```yaml
title: 我的小站
subtitle: ''
description: '记录学习与生活'
keywords: 'Hexo,博客'
author: 你的名字
language: zh-CN
url: https://your-domain.com/

deploy:
  - type: git
    repository: https://github.com/yourname/yourname.github.io.git
    branch: main
```

当前仓库中的 `_config.yml` 已经包含站点标题、作者、URL、归档分页、部署、Algolia、搜索、Feed、站点地图、百度推送、Git 贡献日历等配置。你可以把它当作完整参考，按需替换成你自己的值。

## 文章创作流程
### 新建文章
在终端执行：

```bash
npx hexo new post "我的第一篇文章"
```

这会在 `source/_posts/` 下生成一个以日期加标题命名的 Markdown 文件，例如：

```
source/_posts/2026-10-01-我的第一篇文章.md
```

### 编辑文章
用任意编辑器打开生成的 Markdown 文件，添加 Front-matter 和正文内容。Front-matter 常用字段包括：

| 字段 | 作用 |
| --- | --- |
| `title` | 文章标题 |
| `date` | 文章发布时间 |
| `updated` | 文章更新时间 |
| `tags` | 标签数组 |
| `categories` | 分类数组 |
| `cover` | 文章封面图片 |
| `sticky` | 是否置顶 |
| `mathjax` | 是否需要 MathJax |

当前仓库的脚手架模板位于 `scaffolds/post.md`，你可以参考它来调整新文章的默认结构。

### 预览文章
保存 Markdown 后，刷新 `http://localhost:4000`，就能看到新文章出现在首页或归档页。

如果文章没有显示，请检查：
1. 文件名是否在 `source/_posts/` 下。
2. Front-matter 语法是否正确。
3. 是否使用了非法字符或缩进错误。
4. 是否被加密插件或其他插件隐藏。

## 常见问题与故障排除

### 问题一：端口 4000 已被占用
**现象**：启动 `hexo server` 时报端口冲突。  
**解决方法**：
- 关闭占用 4000 端口的程序。
- 或者临时指定其他端口（具体端口参数取决于 Hexo 版本）。
- 查看终端输出，确认服务实际监听的是哪个端口。

### 问题二：本地能看，但部署后白屏或样式错乱
**排查步骤**：
1. 检查 `_config.yml` 的 `url` 是否填写正确。
2. 检查 `_config.fomalhaut.yml` 中的头像、顶部图、社交图标路径是否可访问。
3. 检查 CDN 资源是否被拦截或跨域失败。
4. 检查部署平台是否启用了缓存，必要时清除缓存。
5. 检查浏览器控制台是否有 404 或跨域错误。

### 问题三：修改模板不生效
**原因**：`.pug` 模板在 Hexo 启动时加载。  
**解决**：修改 `themes/fomalhaut/layout/` 下的模板后，必须重启 `hexo server`。

### 问题四：文章不显示或排序异常
**排查**：
- 检查 `source/_posts/` 下的文件名是否符合日期格式。
- 检查 `_config.yml` 的 `new_post_name` 和 `permalink`。
- 检查 `archive_generator` 的 `per_page`、`yearly`、`monthly`、`order_by`。
- 检查是否误用了加密插件或草稿模式。

### 问题五：评论不显示
**排查**：
1. 确认 `_config.fomalhaut.yml` 中 `comments.use` 已设置为真实可用的评论系统。
2. 如果是 Twikoo，确认 `twikoo.envId` 已填为真实部署地址。
3. 检查浏览器控制台是否有评论服务请求失败。
4. 如果开启了 `lazyload`，滚动到评论区才会加载。

### 问题六：搜索无法使用
**排查**：
- 如果使用 Algolia，检查 `_config.yml` 和 `_config.fomalhaut.yml` 中的 App ID、API Key、Index Name。
- 如果使用本地搜索，确认搜索索引文件已生成。
- 检查网络是否能访问 Algolia 或本地搜索资源。

### 问题七：构建时报依赖缺失或版本不兼容
**解决**：
```bash
rm -rf node_modules package-lock.json
npm install
```

如果仍然报错，检查 Node.js 版本是否为 18、20 或 22。

## 下一步建议
当你成功搭建并预览博客后，可以继续完善以下内容：

1. **替换占位资源**  
   把头像、顶部图、社交图标、封面图换成你自己的图片或图床链接。

2. **配置评论系统**  
   推荐使用 Twikoo，部署服务端后填入 `envId`，并在 `comments.use` 中启用。

3. **配置搜索**  
   小站可用本地搜索；内容较多时可使用 Algolia。

4. **配置部署**  
   根据托管平台（GitHub Pages、Vercel、Cloudflare Pages 等）配置 `_config.yml` 的 `deploy` 或使用仓库提供的部署脚本。

5. **自定义样式与脚本**  
   尽量通过 `_config.fomalhaut.yml` 的 `inject.head` / `inject.bottom` 引入 `source/css/` 和 `source/js/` 中的独立文件，避免直接修改主题源码。

6. **持续写作**  
   使用 `npx hexo new post` 写文章，定期 `generate` 并部署到线上。
